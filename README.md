# 概要说明助手

**把复杂工作讲清楚，让读者在有限时间内理解真正重要的内容。**

`briefing-summary-assistant-zh` 是一个中文 Codex Skill，用于撰写、审阅和修改项目概要、阶段进展、周报、短期汇报与技术工作说明。

它默认站在“第一次接触项目、只有约十分钟阅读时间的认真读者”立场上组织材料，帮助你讲清问题、做法和实质进展。可以根据场景面向导师、负责人、同事或合作方调整表达，没有固定的行业或研究项目背景。

## 适用场景

| 场景 | 帮你讲清什么 |
| --- | --- |
| 项目概要、研究概要 | 为什么开展、解决什么问题、采用什么思路、目前取得什么结果 |
| 阶段进展、阶段总结 | 本阶段做了什么、完成到哪里、形成了什么成果、下一步是什么 |
| 周报、短期工作汇报 | 本期最重要的变化与成果，以及近期安排 |
| 技术或研究工作说明 | 核心机制如何服务项目问题，技术选择为什么有用 |
| 已有文稿审阅与精简 | 主线是否清楚、主次是否合理、术语是否过密、哪些地方值得修改 |

## 写作方式

- **问题先行，技术后置。** 先让读者知道为什么做这件事，再介绍具体做法。技术细节围绕需要解决的问题展开。
- **突出真正的重点。** 按实际贡献和汇报目的分配篇幅，让关键成果获得足够解释，辅助参数与实现细节保持适当比例。
- **控制术语密度。** 先讲概念，再引入名称；只保留理解核心机制所必需的公式、符号和缩写。
- **自然、简洁。** 用具体问题、行动和结果串起叙述，减少套话、重复总结与工作流水账。结构随用途调整，不强制六段式或八段式。
- **忠于当前事实。** 优先使用当前项目的最新材料，明确区分已完成、已取得结果、正在进行和下一步计划，不编造数据、工作量、成果或引用。
- **修改保持连续。** 优先局部修改，保留成熟表达和已经确认的主线；审阅只提出真正影响理解、准确性和表达效果的建议。

### Anti-defensive Writing

采用积极、直接、克制的表达，从材料支持的主要工作和进展出发，不主动堆砌假想质疑、一般性局限、免责声明和风险预案。

与此同时，会影响读者判断的关键未完成事项、实际阻碍、依赖和重大不确定性仍须如实说明。用户明确要求风险或局限分析时，应提供相关事实。成果要准确呈现，不能贬低，也不能夸大。

## 安装到 Codex

本仓库是指令型 Skill，包含 `SKILL.md` 和界面元数据，无需安装额外运行依赖。

将仓库放入个人 Skill 目录，并将文件夹命名为 `briefing-summary-assistant-zh`。

### Windows（PowerShell）

已安装 Git 时，可以执行：

```powershell
$skillPath = Join-Path $HOME ".agents\skills\briefing-summary-assistant-zh"
New-Item -ItemType Directory -Force -Path (Split-Path $skillPath) | Out-Null
git clone https://github.com/lovezmran/summary-assistant.git $skillPath
```

安装后，入口文件应位于：

```text
%USERPROFILE%\.agents\skills\briefing-summary-assistant-zh\SKILL.md
```

没有 Git 时，也可以下载仓库 ZIP，将其解压后的文件夹重命名为 `briefing-summary-assistant-zh`，再放入 `%USERPROFILE%\.agents\skills\`。检查 `SKILL.md` 直接位于该文件夹内，避免多嵌套一层目录。

### macOS / Linux

```sh
mkdir -p ~/.agents/skills
git clone https://github.com/lovezmran/summary-assistant.git ~/.agents/skills/briefing-summary-assistant-zh
```

Codex 支持从个人目录 `~/.agents/skills` 发现 Skill，并根据名称与描述选择使用。安装后若尚未出现在技能列表中，重启 Codex 再检查。参见 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

已经安装的副本无需重复克隆。通过 Git 克隆安装的副本，可在该目录中运行 `git pull --ff-only` 更新；通过 ZIP 安装的副本，可下载新版本并替换对应文件。

## 如何调用

想明确指定这个 Skill，可以使用完整名称：

```text
使用 $briefing-summary-assistant-zh，根据当前项目材料写一份概要说明。
```

日常也可以直接用中文描述需求，例如：

```text
用概要说明助手，把这份项目进展整理成负责人能快速读懂的汇报。
```

Codex 也可以根据任务描述自动选用合适的 Skill。需要明确指定时，使用完整的 `$briefing-summary-assistant-zh` 写法。

## 三个调用示例

### 1. 项目概要

```text
使用 $briefing-summary-assistant-zh，先阅读我提供的当前项目材料，
为首次接触项目的合作方写一份约600字的中文概要。
重点说明为什么开展、要解决什么问题、采用什么思路，以及目前的实质结果。
```

### 2. 阶段进展

```text
用概要说明助手，根据最新工作记录整理一份给导师看的阶段进展。
重点交代本阶段完成的工作、已获得的结果和下一步安排，
把正在进行的工作与已经完成的成果区分清楚，控制在一页以内。
```

### 3. 短期汇报

```text
用概要说明助手，把本周记录整理成一份两分钟口头汇报稿。
突出本期最重要的变化和成果，简要交代近期安排，直接给出可使用的正文。
```

### 审阅与局部修改

```text
用概要说明助手审阅这份汇报。先给整体判断，再提出少量高价值修改。
保留已经成熟的内容，指出需要修改的具体位置，并给出可直接替换的文字。
```

## 提供哪些材料更有帮助

提供项目现有材料、最新工作记录或待修改文稿，并尽量说明受众、用途、篇幅和格式。例如：“给负责人阅读、500字以内、直接交付正文”。已有足够信息时，助手会直接开始；关键事实有冲突时，会指出具体冲突，不自行补造。

正式论文写作和论文审稿不是默认任务。用户明确要求时，可以在指定范围内支持，但不会自动扩展为文献综述、SCI 投稿材料或额外实验计划。
